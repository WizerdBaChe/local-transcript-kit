# local-transcript-maker

**把機器逐字稿的「不確定」變成看得見的東西。**

機器做出來的逐字稿，錯的地方不會自己舉手。讀的人看著一段通順的中文，沒有辦法
知道哪一句是模型在幻聽、哪一段其實是另一種語言、哪幾行是解碼器卡住之後複製貼上
的產物。這個工具不會幫你把逐字稿變正確——它會告訴你**該懷疑哪裡**。

全部在你自己的機器上跑。不上傳、不登入、不需要帳號，錄音和文字都不離開這台電腦。

**第一次用、或想照順序把它驗過一遍**：[`docs/guide-2026-09-11.md`](docs/guide-2026-09-11.md)。
那一份是**照著做**的（打什麼、什麼順序、怎麼知道成功了）；這一份是**查**的
（這是什麼、那個詞什麼意思、那個錯誤代號怎麼辦）。

## 60 秒上手

先把它裝進你自己的 Python（3.12 以上）。它**不會**裝任何第三方套件——
`dependencies = []`，語音引擎活在另一個直譯器裡：

```powershell
pip install -e .
```

裝完之後 `ltm` 這個指令就可以直接用。不想裝的話，把 `src` 放進 `PYTHONPATH`
再用 `python -m ltm` 也一樣；下面的例子都寫成後者，因為它不需要先裝東西。

```powershell
python -m ltm intake "D:\output\演講.aac"
```

它會印出一個 **run 代號**（例如 `演講-86b8bfd9`，後面八碼是檔案內容的雜湊）。
接下來三個指令都用這個代號：

```powershell
python -m ltm decode "演講-86b8bfd9"
```

```powershell
python -m ltm plan "演講-86b8bfd9"
```

```powershell
python -m ltm show "演講-86b8bfd9"
```

`decode` 是唯一會花時間的一步。36.4 分鐘的錄音在這台機器上量到 **177 秒**
（約 3 分鐘；`docs/evidence/two_conditions_2026-09-09.txt`）。
**那次量測是 2026-09-09 的出廠預設，不是今天的**：當時 `multilingual=False`，
而 E-3 之後預設是逐視窗判定語言，還多一個 `language-slots` 階段（約多 11%）。
今天的實測落在 200–252 秒（`docs/evidence/decode_variance_2026-09-16.txt`，
兩份不同長度的錄音），所以「約 3 分鐘」這個量級仍然對，來源那個數字不是。
〔第十三輪 R13a-S6：UAT、issues 與證據腳本三處都補了這個註記，只有 README 漏掉——
**而 README 是唯一一處使用者真的會讀到的地方**。〕整個過程有一行會就地更新的進度，
按 **Ctrl-C 是「請它停下來」而不是砍掉它**——它會把已經寫到一半的東西丟掉，
不留半成品。

## 用看的，不想打指令

**最短的路：雙擊 `<WORKSPACE>/local-transcript-maker\開啟校讀頁.cmd`。**
不用先安裝任何東西——這個工具只用 Python 標準函式庫，所以那個檔案自己把
`src` 掛上去就跑得起來，你唯一需要的是機器上有 Python 3.12 以上（沒有的話
它會告訴你去哪裡裝，然後停在原地等你看完）。

它會開出頁面，並且讓頁面**可以對一個資料夾發動解碼**：

- **把一個資料夾拖到那個 .cmd 上**，頁面就看得到那個資料夾裡的錄音；
- **直接雙擊**，用的是輸出根目錄底下的 `_錄音\`（不存在就當場建），
  把錄音丟進去、在頁面上按「看一次」就會出現。

**它啟動時印出來的那一行就是它被允許看哪裡**，每次都印。這不是囉唆：
「頁面可以開始解碼」跟「頁面看得到你的磁碟」是兩種不同的權限，
一個沒有講出來的授權不算授權。要別的組合（換根目錄、換埠、唯讀）就直接用
下面那個指令，.cmd 刻意不轉送旗標——一個半懂旗標的啟動器比完全不懂的更糟。

```powershell
python -m ltm.ui.serve
```

它會印出一行 `http://127.0.0.1:<埠>/?t=<權杖>`，**然後自己把瀏覽器打開**。
一頁列出所有的 run，點進去就是那一輪的全部：上面是**整份可不可信**
（錄音被切成一段一段，每段的語言與兩個訊號的一致程度），中間是**是哪幾句**
（每一則都帶原文與時刻），下面是**你要不要採納**（勾選框，送出就是採納）。

三件先知道的事：

- **埠與權杖每次啟動都不一樣，網址跟著這個行程活**。Ctrl-C 停掉，網址就失效了。
  這不是沒設定好，是刻意的——這張臉只在你面前存在，關掉就不存在。
- **這一頁只綁在本機**（`127.0.0.1`），別台機器連不到，也沒有帳號可登入。
- **頁面不會自己動你的東西。** 勾選送出走的是跟指令列同一個 `accept`，
  所以一樣是**往前多開一版**，舊的那一版永遠還在。

不要它自己開瀏覽器就加 `--no-browser`；要看別的資料夾就加 `--root <路徑>`。
**它印的第二行就是它正在讀哪個資料夾**——那一行跟你想的不一樣，就是 `--root` 加錯了。

清單最上面還有一塊**解碼面板**：挑一個檔案、按開始，然後你會看到進度真的在動、
可以中途叫它停。它做完之後給你的是**那一輪紀錄的連結，不是內文**——這一頁到
今天為止沒有任何一條路由會把逐字稿吐出來，只有 `/run` 那一頁會。
面板要能挑檔，伺服器就得先被告知可以看哪裡：`--audio-root <資料夾>`（可以給很多次）。
**不給就是不給**——沒有這個旗標的話，面板只能重解你已經用 `ltm intake` 交進來過的東西。

## 跑之前需要什麼

| 東西 | 預設位置 | 換掉的方法 |
|---|---|---|
| 語音引擎的直譯器（faster-whisper 裝在裡面） | 本專案資料夾裡的 `runtime\asr-py\Scripts\python.exe` | 環境變數 `LTM_SIDECAR_PYTHON` |
| 模型權重 | 本專案資料夾裡的 `runtime\models\faster-whisper-large-v3` | 環境變數 `LTM_MODEL_DIR` |
| `ffprobe`（量錄音長度用，要在 PATH 上） | 系統 PATH | — |
| 輸出根目錄 | 環境變數 `LTM_ROOT`；沒設就是家目錄底下的 `TranscriptDesk`（例如 `C:\Users\<你>\TranscriptDesk`） | `--root <路徑>`，或設定 `LTM_ROOT` |

**`runtime\` 不見了怎麼重建。** 這個資料夾不進 git，清理工具把它歸為「第三方、可重新下載」。
2026-10-26 它真的被整包清掉過，2026-10-27 是這樣重建的，沒有重新下載任何東西：

```powershell
# 1. 直譯器：Python 3.12 的 venv，沿用系統已裝的 faster-whisper 1.2.1（原本的 asr-py 也是這個組合）
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" -m venv --system-site-packages runtime\asr-py
# 2. 權重：從 Hugging Face 快取複製 Systran/faster-whisper-large-v3 的 snapshot
#    快取缺 config.json 時，它通常還在 blobs\ 裡（檔名＝內容的 git hash，可用 git hash-object 核對）
```

複製完，`decode` 開跑前會先檢查資料夾裡有沒有 `model.bin`、`config.json`、`tokenizer.json`、
`vocabulary.json`（或 `.txt`），缺哪個就用 `model-missing` 停下來，不會跑到一半才當掉。
**Breeze-ASR-25 是例外**：評測用的那份是在本機從 `MediaTek-Research/Breeze-ASR-25` 轉出來的，
原始權重沒留在快取，轉檔環境放在已經消失的 session 暫存區；要用就得重新下載原始權重再轉一次
（`docs/breeze-eval-2026-10-22.md` §8）。

工具本身只用 Python 標準函式庫，不需要安裝任何套件；faster-whisper 只活在上面那個
獨立的直譯器裡，由子行程呼叫。**根目錄可以指到任何地方，底下的資料夾名稱不能改**
——那是產品跟自己的約定，不是設定。

**GPU 不是必要的，而且你不用自己去猜。** 預設用 `float16`，那是要 GPU 才算得動的
精度。如果這台機器現在沒有可用的顯示卡，**它會停下來問你**：用白話告訴你發生什麼事，
然後讓你決定要不要改用處理器跑（一樣的字，慢好幾倍）。你說要，它就接著跑。

不想被問的話：`--if-no-gpu cpu` 是事先答應，`--if-no-gpu fail` 是直接停。
在沒有終端機的環境（腳本、排程）它**不會替你答應**——它會把該打的旗標印出來然後停，
因為一個你看不到的降級比一次失敗更糟。實測同一段 60 秒的錄音，GPU 的 `float16`
跟 CPU 的 `int8` 解出來都是 26 句。

**不要把上面那句讀成「int8 等價」。** 那是**沒有 GPU 時的退路**，不是省顯示記憶體的
辦法。2026-09-17 在同一張卡上量過同一段 600 秒（`docs/evidence/compute_type_cost_2026-09-17.txt`）：
`int8` 與 `int8_float16` 確實各省 **1,888 MiB**，但同一段從 121 段變成 141–146 段、
**最長連續重複從 1 段變成 14 段**、中文字從 405 掉到 370，而且**兩次跑出兩份不同的稿子**
（float16 在這段上跑了十二次都是同一份）。那 14 段重複正是這個工具存在的理由，
用 1.9 GB 去換它不划算。`float32` 更不用考慮：載入就吃掉 **7,773 MiB／8,151**，
而且一次 120 秒解碼要 551.7 秒。**所以出廠預設是 `float16`，而且暫時不打算改。**

## 產出長什麼樣

```
<輸出根目錄>/                     ← LTM_ROOT，或家目錄底下的 TranscriptDesk
  _intake/                       ← 你交進來的檔案「在哪裡」的指標（不複製錄音本身），也記它從哪裡來
  _錄音/                          ← 你自己丟錄音進來的地方；只有雙擊啟動器會建它，產品只讀不寫
  校讀/
    演講-86b8bfd9/
      _origin.json               ← 這個 run 的身分、每一版的解碼設定與出處
      時軸/  演講.r000.zh.srt     ← 有時間碼的
      全文/  演講.r000.zh.txt     ← 純文字
      _findings/ r000.json       ← 這一輪找到什麼
      _plans/    r000.json       ← 這一輪的完整計畫（含四層量測結果）
  _citable/                      ← 你明確授權「值得引用」的版本才會進來
```

**錄音本身不會被複製。** 一場 53 MB 的演講複製一份是沒人要求的成本；`_intake/`
存的是指標，run 代號後面的八碼是**內容**的雜湊，所以同一個檔案換個名字交進來，
仍然解析到同一個 run。

`r000`、`r001` 是**修訂版本**。每跑一次 `decode` 或每接受一次修改，就多一版，
舊的一版不會被蓋掉。每一版的解碼設定分開記在 `_origin.json` 裡——同一個錄音用
兩種設定各解一次來對照，是這個工具預期的用法。

## 十個動詞

| 指令 | 做什麼 |
|---|---|
| `intake <路徑>` | 把一個錄音或字幕檔登記進來，回一個 run 代號。可加 `--from-url <網址>`、`--from-note <短註記>` 記下檔案從哪裡來（只記錄，不連網） |
| `decode <run>` | 跑引擎、切出四層、跑偵測，放下 `r000` |
| `detect <run>` | 對已經量好的那一版**重跑偵測**（不重解碼），另外放一輪 |
| `plan <run>` | 看一版的計畫：找到什麼、建議刪什麼 |
| `show <run>` | 看一版的結構化事實：數量、語言段落、檔案在哪 |
| `runs` | 列出這個根目錄底下所有的 run |
| `accept <run>` | 採納計畫裡的修改（人跟代理都可以，**版本會記下是誰做的**） |
| `cite <run> --rev <版本> --granted-by <人名>` | 把一版複製進 `_citable/`，並留下授權紀錄 |
| `open <路徑>` | 打開一個檔案給人看 |
| `cancel --state <狀態>` | 請正在跑的工作停下來 |

常用旗標：

- `--json`：把回應印成 JSON 而不是人話。代理（agent）就是走這條路。
- `--rev r001`：指定版本，省略就是最新的一版。
- `--no-vad`：**連靜音一起解碼**。預設是開 VAD 的。
- `--language zh`：**整份檔案釘住一種語言**。預設不釘。**要搭 `--no-multilingual` 才能用**
  ——單獨下 `--language` 會被擋下來，並告訴你缺哪個旗標（原因見下一條）。
- `--no-multilingual`：**關掉逐段判斷語言**。預設是開的（2026-09-16 起）：
  引擎每解一個視窗就重新判斷一次這段在講什麼語言。關掉的時候，一份中英混雜的錄音
  曾經被整份寫成英文、**一個中文字都沒有**（I-20）；打開之後同一份錄音找回七千多個中文字，
  另外兩份純中文錄音沒有任何可量到的變化，時間還略少。它跟 `--language` 不能一起開：
  引擎會無聲地推翻你釘的語言，紀錄上卻寫著「釘選生效」。
- `--no-language-slots`：跳過第二個語言訊號（省下約 7% 的時間，代價是每一段語言
  都會變成「分不出來」，因為沒有第二個訊號可以比對）。

`--no-vad` 跟 `--language` 這兩個旗標不是裝飾。`docs/` 裡量到的那些數字
（659 / 789 / 936 句）都是用 `--no-vad --language zh`（今天要重現得寫成
`--no-vad --language zh --no-multilingual`）量的，出廠預設不是那個設定，
出來的逐字稿也不一樣。**這件事本身是一個待你裁決的問題**，寫在
`docs/uat-2026-09-09.md` 的第一項。

## 怎麼讀它給你的東西

### finding 跟 note

- **finding**：有**兩個以上**互相獨立的訊號指向同一段，工具才會說「這裡有問題」，
  並且提出具體的刪除建議。**有一個例外，而且是你 2026-09-09 裁決的**：
  同一句話**連著出現 5 次以上**，這件事本身就夠，不必等第二個訊號。
  理由是實測出來的——機器**很鎮定地**重複自己的時候，它自己不會回報任何異常，
  所以第二個訊號永遠不會來，而那正是最該讓你看到的一種壞掉。
  代價是：你**真的**連講 5 次的話（點名、倒數、逐項唸），也會被建議刪掉。
  建議永遠只是建議，要你點頭才會動到文字。
- **note**：它會被標出來讓你看，但**不會**變成刪除建議。有三種，
  而且**每一則都會說自己是哪一種**：只有**一個**訊號（`single-signal`）、
  訊號夠但**沒有可提的修改**（`no-action`）、
  或是**差一句就到門檻**（`near-threshold`）。三種印出來的話不一樣，
  因為它們對你的意思不一樣——`near-threshold` 是叫你去看，另外兩種不是。
- 一個訊號都沒有的候選段落也被記下來了（在 `_plans/` 裡），只是不會出現在摘要上。

會提名的只有「重複」：同一句話連著出現五次以上、一句話裡面自己重複、或是解碼器
自己回報的異常（溫度上升、壓縮比爆掉、對數機率掉下來）。**工具不會因為一句話
「聽起來怪怪的」就標記它**——那需要語意判斷，而語意判斷的模型在這個里程碑裡
是刻意缺席的。

**`near-threshold` 是最值得你自己去看的一種 note，不是最不值得的。** 它的意思是
「差一句就到門檻」——**而門檻的另一邊現在是直接建議刪除**，所以這一則就是
「再一次解碼它就會變成建議刪除」的那一種。
這不是比喻：同樣的旗標跑七次會得到七份不同的逐字稿，最長同文串在 2 到 10 之間跳，
而中位數正好壓在門檻上（見下一節）。**這個工具現在讓那個抖動只改變它多有把握，
不再改變它的結論**——以前 4 句是完全看不見，5 句是「建議刪除」。

### 語言段落與 agreement

`show` 會列出錄音被切成幾段、每一段是什麼語言，以及一個 `agreement` 數字。
那是**文字面判斷**跟**聲音面判斷**兩邊的一致程度。

`agreement < 0.5` 一律顯示 **`undetermined`（分不出來）**。這不是一個調出來的
門檻，而是定義：兩個訊號同意不到一半，就是沒有共識。**「分不出來」是誠實的答案，
不是失敗**——比起用單一訊號硬給一個語言標籤，這正是這個工具存在的理由。

### 同一個檔案跑兩次，結果不會完全一樣

這件事你必須先知道：**重跑一次 `decode`，出來的逐字稿不會跟上一次一模一樣。**
GPU 上的 float16 解碼本來就不是位元可重現的（這在語音辨識裡是常態，不是這個
工具的 bug）。

實測：同一份錄音、同樣的旗標解碼 **7 次**，得到 **7 份不同的逐字稿**
（句數 661–728），其中 **2 次**說「這裡建議你刪掉」、**5 次**說「沒問題」
（`docs/evidence/positive_control_2026-09-09.txt`）。最長同文串在 2 到 10 之間跳，
**中位數正好是 5**——而 5 就是「這裡有問題」的門檻。判準壓在雜訊正中央。

**已經改掉的一半**：現在 4 句會被記成 `near-threshold` 的 note，5 句才是 finding。
所以抖動改變的是**它多有把握**，不再是**它的結論**。代價量過了：在那份 36 分鐘的
錄音上，這個放寬總共多出**一個** note，而那一個是誤報（一句真的講了四次的話）。

**沒改掉的一半**：門檻只是往下移了一格，沒有消失——連續 3 句仍然完全看不見。
所以：

- **不要重跑一次來「確認」上一次的結果**——不一樣不代表哪一次錯了。
- 每一版的逐字稿指紋記在 `_origin.json` 的 `text_sha256` 裡。要問「這兩版是不是
  同一份文字」，比那個欄位，**不要比句數**（句數會在不同的文字上撞在一起）。
- 舊的版本不會被蓋掉，所以你昨天看過的那一版永遠還在。

這一項在 `docs/issues-2026-09-09.md` 是 I-1，而且它是需要你裁決的第一批項目之一。

### 未驗證標記

計畫摘要裡如果出現 `no-token-layer`，意思是「這個建議需要字級對齊才能完全確認，
而字級對齊這一層里程碑 1 沒有建」。如果**根本沒有任何建議落在這個範圍內**，
它會直接說「沒有東西在範圍內」，而不是印一個 `0` ——一個沒有分母的 `0` 會被讀成
「全部通過」，那跟事實相反。

## 這個工具刻意不做的事

- **不連網、不登入、不要帳號。** 核心路徑上沒有任何網路呼叫。
- **不改你的原始錄音，也不覆寫你的舊版本。**
- **不自己判斷語意。** 語意判斷模型（Advisor）在里程碑 1 是**整個不存在**的，
  不是關掉——沒有那個模組、沒有那個狀態、沒有那些欄位。
- **沒有字級對齊。** 你如果明確要求 `--word-level`，它會**大聲失敗並說出缺哪一層**，
  而不是安靜地回一份句級的結果假裝照做了。
- ~~**`accept` 只有人能做。**~~ **這條你在 2026-09-09 拿掉了**：代理現在可以採納。
  換來的保證是紀錄——每一個版本都記著它是**人**還是**代理**做的
  （`_origin.json` 的 `face`）。沒有那個欄位的舊版本代表「寫在這個欄位存在之前」，
  **不會被當成人做的**。證明不會被繞過的部分沒動：沒有腳本就不寫，
  而且「改完能不能還原」是先在記憶體裡證明過才落地的。
- **`cite` 一定要有人的授權紀錄**（誰、何時、範圍、用什麼方式），而且範圍只能是
  單一個 `<run>/<版本>`。沒有常設授權。

## 出事的時候

| 你看到 | 意思 | 怎麼辦 |
|---|---|---|
| `engine failed: interpreter-missing` | 找不到語音引擎的直譯器 | 檢查 `LTM_SIDECAR_PYTHON` |
| `engine failed: model-missing` | 找不到模型權重，**或資料夾在但缺了引擎要的檔案**（`model.bin`、`config.json`、`tokenizer.json`、`vocabulary.json`／`.txt` 其中之一）。下載中斷的 Hugging Face 快取就會這樣 | 檢查 `LTM_MODEL_DIR`，看資料夾裡這四樣是否都在 |
| `engine failed: probe-missing` | PATH 上沒有 `ffprobe` | 裝 ffmpeg，或把它加到 PATH |
| `engine failed: silent` | 子行程在時限內一個字都沒吐出來，**而且我們不知道為什麼** | 看它指給你的 stderr 檔案。這個代號說的是「我們觀察到什麼」，不是「我們猜是什麼」 |
| `engine failed: crashed` | 子行程死了，**而且我們沒有判定出是哪一種**。為什麼一定在它指給你的那個 stderr 檔案裡 | 先打開那個檔案再懷疑別的。代號只說「死了」是刻意的——把子行程的錯誤訊息搬進回應等於開一條自由文字通道（INV-14） |
| 它問你「要不要改用處理器跑」 | 這台機器現在沒辦法用顯示卡做這個運算 | 回 `y` 就繼續（慢，但字一樣）。這個判斷是**問過** ctranslate2 這台機器支援哪些運算才下的，不是去比對錯誤訊息的字串 |
| `engine-failed`＋`compute-unsupported`（`--json` 之下） | 同上，但這是機器面 | 代理不會被問問題：改用 `compute_type="int8", device="cpu"` 再呼叫一次，那一次呼叫本身就是同意 |
| `unknown record schema 'ltm/origin/1'` | 這個 run 是舊版本結構寫的 | 重新 `decode` 一次就會產生新的。里程碑 1 沒有轉檔程式 |
| 進度停在某個階段但沒有分母 | 那個階段本來就沒有分母 | 它會直接說「這個階段沒有分母」，而不是畫一條填不滿的進度條 |
| 進度條走到最後停在 100%，`_origin.json` 裡卻多出一個 `timestamps_past_end` | 引擎給的最後一句結束時間，比 `ffprobe` 量到的檔案長度**還長**（實測 0.44 秒） | **正常，不用管。** 進度條停在終點，多出來的秒數另外記著。字幕本身的時間戳沒有被改——一句字幕結束在檔案長度之外，是真的發生了，拿它去跳轉的東西需要知道 |

## 給要用程式驅動它的人

每個動詞都可以 `--json`，而且**兩張臉呼叫的是同一個函式**（有測試在盯著這件事）。
回應裡沒有任何自由文字欄位——所有字串不是識別碼就是封閉集合裡的狀態名，這樣
代理讀到的東西不會摻進一段可以被當成指令的散文。

介面契約、狀態機、不變式清單**跟著套件一起出貨**，只有一份，在
[`src/ltm/AGENTS.md`](src/ltm/AGENTS.md)（英文，寫給機器讀的）。不要另外抄一份——
直接跟它要：

```powershell
python -m ltm agent guide          # 印出那份契約（裝好之後：ltm agent guide）
python -m ltm agent guide --path   # 只印它在哪
python -m ltm agent which          # 這台機器上 ltm 裝了沒、在哪、跑在哪個直譯器
```

`ltm agent` **不是動詞**，是一個放「關於這個工具本身」的問題的命名空間；底下的
東西不讀也不寫任何 store（有一個性質測試盯著這件事）。

`agent which` 把**找得到**和**裝好了**分成兩件事回答，因為這兩件事會不一樣：

```
on PATH      : no
interpreter  : C:\...\Python312\python.exe
importable   : yes  (so `python -m ltm` works here; `ltm` does not)
```

上面那個狀態就是「這個 repo 還沒 `pip install -e .`」——`python -m ltm` 能跑，
`ltm` 不能。看到 `onPath: no` 不代表這個工具不在。

要讓你自己的代理（Claude Code、Codex、Droid…）知道這個工具在，可以請它在你自己的
設定檔裡放一段指路的文字。**它只會寫在兩個標記之間，其他一個位元都不動**，而且
**永遠不碰你的 PATH、也不會幫你安裝任何東西**：

```powershell
python -m ltm agent register --target agents-md --dry-run   # 先看它要寫什麼
python -m ltm agent register --target agents-md             # 真的寫
python -m ltm agent register --target agents-md --remove    # 拿掉，檔案回到原樣
```

`--target` 只決定預設檔名（`--file` 可以蓋過去），計畫裡一定會印出它最後選的
絕對位置，所以你不必相信這張對照表。標記如果已經壞掉（少一半、多一組、順序相反），
它會**拒絕並且什麼都不寫**，不會自作主張幫你修。

架構與管線在 [`docs/architecture-2026-09-09.md`](docs/architecture-2026-09-09.md)。
